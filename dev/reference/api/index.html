High-level API (not exported)

Functions named like those of LinearAlgebra, owned by OxiBLAS and not exported: call them as OxiBLAS.lu, OxiBLAS.ldiv, etc. They are distinct from the functions of LinearAlgebra (OxiBLAS.lu !== LinearAlgebra.lu). The factorization types are subtypes of LinearAlgebra.Factorization.

Sources: src/api/.

OxiBLAS.BunchKaufman — Type
OxiBLAS.BunchKaufman{T,E} <: LinearAlgebra.Factorization{T}

Symmetric indefinite factorization with Bunch–Kaufman pivoting (1×1 and 2×2 blocks): A[p,p] = L·D·Lᴴ, or L·D·Lᵀ for a complex symmetric matrix. It wraps an engine of type E:

  • LDLFactor (dense);
  • SparseLDLFactor (sparse, with the MA57 threshold).
source
OxiBLAS.Cholesky — Type
OxiBLAS.Cholesky{T,E} <: LinearAlgebra.Factorization{T}

Cholesky factorization A = L·Lᴴ, which wraps an engine of type E:

  • CholeskyFactor (dense, lower triangle);
  • MultifrontalCholeskyFactor (sparse: A[p,p] = L·Lᴴ).

The info field is nonzero when the factorization failed (check=false).

source
OxiBLAS.Eigen — Type
OxiBLAS.Eigen{T,V,M,W} <: LinearAlgebra.Factorization{T}

Eigendecomposition A·vectors = vectors·Diagonal(values). It shares the engine's arrays without copying them.

  • A Hermitian or real symmetric input goes to eigen_hermitian (real values, in ascending order).
  • Any other input goes to eigen_general (complex values).
  • values, vectors = F destructures it.
  • It provides no ldiv!: LinearAlgebra.Eigen has no solve either.
source
OxiBLAS.GeneralizedEigen — Type
OxiBLAS.GeneralizedEigen{T,V,M,W} <: LinearAlgebra.Factorization{T}

Generalized eigendecomposition A·vectors = B·vectors·Diagonal(values). It shares the engine's arrays without copying them.

  • Hermitian/real symmetric wrappers go to eigen_generalized: Cholesky of B (which must be positive definite), then the Hermitian EVD, with real values and B-orthonormal vectors.
  • Any other matrices go to eigen_pencil (QZ, then the pencil vectors), where values = α ./ β, possibly infinite.
  • values, vectors = F destructures it. It provides no ldiv!, like LinearAlgebra.GeneralizedEigen.
source
OxiBLAS.GeneralizedSchur — Type
OxiBLAS.GeneralizedSchur{T,C,E} <: LinearAlgebra.Factorization{T}

Generalized Schur (QZ) decomposition A = Q·S·Zᴴ, B = Q·T·Zᴴ (QZFactor). It has the properties S, T, Q, Z, α, β and values = α ./ β.

source
OxiBLAS.Hessenberg — Type
OxiBLAS.Hessenberg{T,E} <: LinearAlgebra.Factorization{T}

Hessenberg reduction A = Q·H·Qᴴ (HessenbergFactor).

  • F.H is an UpperHessenberg matrix.
  • F.Q is an implicit HessenbergQ.
  • It provides no ldiv!, since the engine has no shifted Hessenberg solve.
source
OxiBLAS.HessenbergQ — Type
OxiBLAS.HessenbergQ{T,E} <: LinearAlgebra.AbstractQ{T}

The Q factor of a Hessenberg reduction, applied through its reflectors (apply_hessenberg_q!).

source
OxiBLAS.LDLt — Type
OxiBLAS.LDLt{T,E} <: LinearAlgebra.Factorization{T}

LDLᵀ factorization without pivoting: A[p,p] = L·D·Lᴴ, with D diagonal and p a fill-reducing ordering (identity for a dense matrix). It wraps an engine of type E:

  • LDLFactor (dense, pivot=:none);
  • SparseLDLFactor (sparse, pivot=:none).
source
OxiBLAS.LQ — Type
OxiBLAS.LQ{T,E} <: LinearAlgebra.Factorization{T}

LQ factorization A = L·Q. It is stored in Householder form as the QR factorization of Aᴴ, which is what lq_factor computes; Q stays implicit. F \ b returns the minimum-norm solution of a wide system.

source
OxiBLAS.LQPackedQ — Type
OxiBLAS.LQPackedQ{T,E} <: LinearAlgebra.AbstractQ{T}

The Q factor of an LQ factorization, which is the adjoint of the Q factor of the QR factorization of Aᴴ. Matrix(Q) gives the thin min(m,n)×n basis.

source
OxiBLAS.LU — Type
OxiBLAS.LU{T,E} <: LinearAlgebra.Factorization{T}

LU factorization with row pivoting, which wraps an engine of type E:

  • LUFactor (dense): F.L*F.U == A[F.p,:];
  • MultifrontalLUFactor (sparse): F.L*F.U == A[F.p,F.q].

The type is mutable so that lu!(F, A) can refactorize in place.

source
OxiBLAS.QR — Type
OxiBLAS.QR{T,E} <: LinearAlgebra.Factorization{T}

Householder QR factorization A = Q·R (QRFactor). F.Q is an implicit AbstractQ, and F \ b returns the least-squares solution for a tall A and the minimum-norm solution for a wide one.

source
OxiBLAS.QRPackedQ — Type
OxiBLAS.QRPackedQ{T,E} <: LinearAlgebra.AbstractQ{T}

The Q factor of a QR factorization, applied through its Householder reflectors and never formed. Matrix(Q) gives the thin m×min(m,n) basis, as for LinearAlgebra's QR.

source
OxiBLAS.QRPivoted — Type
OxiBLAS.QRPivoted{T,E} <: LinearAlgebra.Factorization{T}

QR factorization with column pivoting, A[:,p] = Q·R (PivotedQRFactor).

  • The solution is the minimum-norm one: the numerical rank is read from the diagonal of R, with |Rᵢᵢ| > min(m,n)·eps·|R₁₁|.
source
OxiBLAS.QRSparse — Type
OxiBLAS.QRSparse{T,E} <: LinearAlgebra.Factorization{T}

Multifrontal sparse QR factorization (SparseQRFactor) with the SPQR contract Q*R == A[prow,pcol]. The engine folds its row reordering into Q (transpositions stored as reflectors), so prow is the identity. Its methods are in linalgapisparse.jl.

source
OxiBLAS.SVD — Type
OxiBLAS.SVD{T,Tr,E} <: LinearAlgebra.Factorization{T}

Singular value decomposition A = U·Diagonal(S)·Vt (SVDFactor).

  • F \ b returns the minimum-norm least-squares solution. Singular values at or below eps·S[1] are dropped, as in LinearAlgebra.
  • U, S, V = F destructures the factorization.
source
OxiBLAS.Schur — Type
OxiBLAS.Schur{T,C,E} <: LinearAlgebra.Factorization{T}

Schur decomposition A = Z·T·Zᴴ (SchurFactor). For real input, T is real quasi-triangular. It has the properties T, Z (also vectors) and values, and destructures as T, Z, values = F.

source
OxiBLAS.SparseQRQ — Type
OxiBLAS.SparseQRQ{T,E} <: LinearAlgebra.AbstractQ{T}

The Q factor of a sparse QR factorization, which is a list of sparse reflectors (sparse_apply_q!).

source
OxiBLAS.TriangularEngine — Type
OxiBLAS.TriangularEngine{T,S,K}

Engine of an OxiBLAS.LU for a matrix that is already triangular: dense (UpperTriangular…), bidiagonal, diagonal, triangular BandedMatrix or triangular PackedMatrix.

  • Solves are substitutions with the matching kernel: trsm!/trsv! (dense), tbsv! (band; a bidiagonal is stored as a 2×n band), tpsv! (packed), or a division (diagonal). They cost O(n²) for dense storage and O(n·k) for a band.
  • For an upper (or diagonal) matrix, it is the partial-pivoting LU (L = I, p = identity).
  • For a lower matrix, it is the LU without pivoting, L = A·D⁻¹ and U = D. It is used only by factorize, since lu (RowMaximum) has to pivot.
  • src is the engine's own copy of the input, and kernel the storage handed to the kernel.
source
OxiBLAS._has_pos_real_diag — Function
OxiBLAS.factorize(A)

Chooses a factorization from the structure of A:

  • square, Hermitian: Cholesky if it is positive definite, otherwise BunchKaufman;
  • other square matrices: LU;
  • rectangular: QRPivoted.

Triangular and diagonal structures are not detected. Unlike LinearAlgebra.factorize, the result is never a LinearAlgebra wrapper, whose solves would go through BLAS.

OxiBLAS.cholesky — Function
OxiBLAS.cholesky(A, [NoPivot()]; check=true) -> OxiBLAS.Cholesky

Cholesky factorization of a Hermitian positive definite matrix (cholesky_factor).

  • Accepts Hermitian, real Symmetric and plain matrices; a plain matrix is checked for being Hermitian.
  • check=false returns a factorization whose issuccess is false instead of throwing PosDefException.
  • cholesky!(A) factors in place: the lower triangle of A (a Matrix or a strided view of floating type) is overwritten by L, its strict upper triangle is zeroed, and A becomes F.factors. For a wrapper with uplo='U', the conjugated upper triangle is first mirrored into the lower one inside the parent.
source
OxiBLAS.cholesky(A::SymTridiagonal{<:Real} / BandedMatrix / PackedMatrix / Diagonal; check=true)

Cholesky factorization in the storage of A:

  • band (band_cholesky, O(n·kd²)): F.L is a lower triangular BandedMatrix;
  • packed (packed_cholesky): F.L is a triangular PackedMatrix;
  • diagonal: F.L is a Diagonal.

A must be symmetric (real) or Hermitian in its own storage; a general or triangular BandedMatrix/PackedMatrix gets an ArgumentError.

OxiBLAS.exp — Function
OxiBLAS.exp(A), OxiBLAS.log(A), OxiBLAS.sqrt(A), OxiBLAS.sin(A), OxiBLAS.cos(A)

Matrix functions on the native engines:

  • matrix_exp: Padé scaling and squaring;
  • matrix_log: complex Schur, then inverse scaling and squaring;
  • matrix_sqrt: complex Schur, then triangular recurrence;
  • matrix_sin, matrix_cos: through exp(±iA).

On a number they are Base's functions. No other type falls back to Base/LinearAlgebra.

The engines exploit no structure: they make one working copy of any AbstractMatrix, which is passed to them as is. The result keeps the structure that f preserves:

InputResult
DiagonalDiagonal, entry by entry (O(n))
upper/lower triangular (dense, Bidiagonal, triangular band/packed)UpperTriangular/LowerTriangular
Hermitian (wrapper, Hermitian band/packed)exp/sin/cos: Hermitian. log/sqrt: Hermitian eigendecomposition V·f(λ)·Vᴴ, as in LinearAlgebra; Hermitian if A is positive definite (log) or semidefinite (sqrt, every λ ≥ -n·eps·max abs(λ)), otherwise a full complex matrix with the branch f(complex(λ)), never forced Hermitian
symmetric (Symmetric, SymTridiagonal, symmetric band/packed)Symmetric (f(A)ᵀ = f(Aᵀ))
Tridiagonal, general BandedMatrix, otherfull matrix (dense in general)

The imaginary part is dropped only when the result is real mathematically:

  • sin and cos of a real matrix;
  • log of a real symmetric positive definite matrix, sqrt of a real symmetric positive semidefinite one;
  • log/sqrt of a real triangular matrix with a positive diagonal.

OxiBLAS.ldiv! — Function
OxiBLAS.ldiv!(Y, F::Factorization, B; workspace=nothing) -> Y
OxiBLAS.ldiv!(Y, A::AbstractMatrix, B; workspace=nothing) -> Y

Solves A*X = B and writes X into Y, which has size(A, 2) rows and as many columns as B.

  • F is any factorization with a LinearAlgebra.ldiv!(F, X) method: the OxiBLAS ones, and their transpose/adjoint. It is reused as it is.
  • A is factorized first with OxiBLAS.factorize (dense, structured or sparse input). An input that it does not accept gets a MethodError.
  • B is never modified, except with Y === B on a square system, which solves in place. A Y that only partially overlaps B is rejected.
  • A tall F (m > n) gives the least-squares solution, a wide one (n > m) the solution of that factorization's own ldiv! (the minimum-norm one for dense QR/LQ); the sparse QR has no wide solve.
  • workspace (OxiBLAS extension beyond LinearAlgebra.ldiv!).
    • Why: For a tall orthogonal factorization (QR, QRPivoted, QRSparse, or LQ' with m > n), the in-place primitive LinearAlgebra.ldiv!(F, X) applies Qᴴ to an m-row buffer before extracting the n solution rows. Because Y only has n < m rows and B must not be overwritten, an m-row working buffer X is required.
    • When you do NOT need it: On square systems (m == n), wide systems (n > m, where Y itself has n > m rows and serves as the working buffer), SVD factorizations (which project into rank-sized scratch and write directly into Y), or when B is sparse (whose dense copy is reused in place), OxiBLAS.ldiv! already avoids allocating X with workspace=nothing.
    • When and how to use it: When solving repeated tall least-squares systems (m > n) in a hot loop with a dense B and QR / QRPivoted / QRSparse / LQ', preallocate ws = Vector{T}(undef, m) (or Matrix{T}(undef, m, nrhs)) once per task and pass workspace=ws to eliminate the m-row buffer allocation. workspace must have at least (max(m, n), size(B, 2)) elements, 1-based indexing, must not alias Y or B, and must be exclusive to the calling task during the call.
  • Y must be a dense array: a solution is dense. A sparse B is read through a dense copy.
  • The solve runs in the factor's element type. A real factor and a complex B of the same precision are solved as two real systems.
source

Sparse LU factorization with threshold pivoting (multifrontal_lu, ordering=:auto), giving F.L*F.U == A[F.p,F.q]. With check=false, a singular matrix returns a factor with a zero diagonal entry in U and issuccess(F) == false.

source
OxiBLAS.lu(A::Tridiagonal / SymTridiagonal / Bidiagonal / Diagonal / BandedMatrix; check=true)

source
OxiBLAS.mul! — Function
OxiBLAS.mul!(C, A, B, α=true, β=false)

C ← α·A·B + β·C with OxiBLAS kernels, for dense matrices and vectors (and their transposes/adjoints and views), LinearAlgebra structured matrices (Diagonal, triangular, Symmetric/Hermitian, Bidiagonal/Tridiagonal/ SymTridiagonal), SparseArrays matrices and vectors, OxiBLAS sparse formats and 2-D SparseTensors. C may be dense, Diagonal or sparse (SparseMatrixCSC, SparseVector, CSRMatrix, CSCMatrix, SparseTensor); a sparse destination receives the exact pattern of the result. β=0 never reads C. Operands whose element type differs from C's are converted, keeping their structure and storage format. Triangular/Symmetric/Hermitian wrappers of a sparse matrix are handled as the sparse matrix they denote (never densified).

Aliasing: an operand whose storage overlaps C (the same array, overlapping views, a Diagonal or structured wrapper of such data) is copied first, so the result is always that of non-overlapping operands.

A sparse destination is filled from a temporary product: sparse when both operands are sparse, dense when one of them is dense (that product is dense in general anyway).

OxiBLAS.sylvester — Function
OxiBLAS.sylvester(A, B, C)

Solution X of A·X + X·B + C = 0, LinearAlgebra's convention. Bartels–Stewart on the native engines:

  1. Schur forms A = U·S·Uᴴ and B = V·T·Vᴴ (schur_factor).
  2. S·Y + Y·T = -Uᴴ·C·V, solved by generalized_sylvester (TGSYL) with the pencils (S, I) and (-T, I) and a zero second right-hand side, which forces R = L.
  3. X = U·Y·Vᴴ.

The equation has a unique solution only when no λᵢ(A) + μⱼ(B) is zero.
