Interface Julia indépendante

Toutes les fonctions numériques travaillent avec des tableaux à indices commençant à 1. Les entrées/sorties flottantes utilisent un même type parmi Float32, Float64, ComplexF32 et ComplexF64. Les opérations vectorielles génériques acceptent également certains autres nombres, sans promesse de performance ou de couverture de test. Les sorties doivent offrir des entrées logiques distinctes et être modifiables.

algorithm sélectionne explicitement une famille GEMM. kernel peut valoir :auto, :scalar, :neon, :avx2, :avx512 ; une ISA indisponible provoque une erreur avant toute écriture. Sur les anciennes versions Julia sans interrogation fiable du CPU cible, x86 utilise le repli scalaire. kernel_info(T) rapporte la voie choisie ; pour les complexes, lanes compte les éléments complexes, le vecteur LLVM contenant deux fois plus de composantes réelles.

Le constructeur GemmWorkspace(T,m,n,k;config,workers) réserve des panneaux réutilisables de taille bornée par les blocs. La configuration passée à l’appel doit tenir dans ces capacités ; un workspace trop petit provoque une erreur. Les champs internes ne doivent pas être redimensionnés ou modifiés par l’appelant. Le noyau lui-même n’alloue pas de panneau. Les appels possèdent encore un petit coût d’allocation de contrôle, consigné dans les benchmarks.

PackedMatrix(data,n;uplo,kind,unit) emploie l’ordre compact BLAS colonne par colonne. pack_matrix(A;...) crée ce stockage. kind vaut :symmetric, :hermitian ou :triangular. Les opérations dédiées sont spmv!, hpmv!, tpmv!, tpsv!, spr!, spr2!, hpr!, hpr2!.

BandedMatrix(data,m;kl,ku,kind=:general,uplo=:U,unit=false) interprète le stockage BLAS data[ku+1+i-j,j]. Les matrices structurées sont carrées et utilisent une seule bande : diagonale à la ligne kd+1 en supérieur, 1 en inférieur. band_matrix(A;...) copie seulement la bande. Les fonctions gbmv!, sbmv!, hbmv!, tbmv!, tbsv! consomment cet adaptateur.

CSRMatrix(m,n,rowptr,colind,values) copie et valide les buffers, en indices Julia à partir de 1. Les doublons dans une ligne sont rejetés. Les colonnes peuvent être non triées. Ne pas modifier ensuite les invariants structurels. sparse_mul!(y,A,x,α,β;trans=:N) parcourt les non-zéros en Julia. cg(A,b;rtol,atol,maxiter,x0,diagonal=nothing) suppose A hermitienne définie positive, et retourne x/converged/iterations/residual/reason. La convergence est confirmée sur le résidu réellement recalculé. diagonal fournit éventuellement une diagonale de Jacobi réelle positive ; elle ne construit pas un préconditionneur avancé. Les sorties ne peuvent pas recouvrir le stockage CSR.

Les BLAS 3 structurés réutilisent les options GEMM algorithm, kernel, threaded, workspace, config. SYMM/HEMM lisent le triangle sélectionné au moment d'empaqueter les panneaux. TRMM/TRSM utilisent une décomposition récursive avec blocksize=8 pour les feuilles ; SYRK/SYR2K/HERK/HER2K et GEMMT parcourent les tuiles du seul triangle demandé, avec blocksize=128. Une tuile diagonale est temporaire ; l'autre triangle de C reste exactement inchangé. Les cas aliasés prennent les snapshots nécessaires avant d'écrire.

gemmt!(C,A,B,α=1,β=0;uplo=:U,transA=:N,transB=:N,...) calcule C[triangle] ← α op(A) op(B) + β C[triangle] pour C carrée. A et B peuvent être rectangulaires ; N/T/C sont indépendants. β=0 ne lit aucune ancienne entrée de C ; α=0 ou K=0 ne lit pas A/B. Un workspace pour les mises à jour de rang k ou GEMMT doit couvrir (min(n,blocksize),min(n,blocksize),k) ; pour TRMM/TRSM, (size(B,1),size(B,2),size(A,1)) convient à tous les sous-problèmes.

ConvergenceError signale une limite d'itérations atteinte. Les colonnes de Z sont des vecteurs de Schur ; les vecteurs propres généraux restent à porter. Les sorties SVD sans vecteurs mettent U/Vt à nothing.

ROTM accepte les vues inversées et à strides non unitaires. Les sorties contiguës utilisent des paquets SIMD LLVM (NEON localement, formes x86 non validées matériellement) ; kernel=:scalar choisit les boucles génériques. Les deux sorties d'une transformation non identité doivent être disjointes, sans indices répétés. L'identité ne lit/écrit pas les vecteurs. Les paramètres peuvent recouvrir une sortie : les champs nécessaires sont copiés dans la valeur immuable avant mutation. Flags 0 et 1 ignorent les coefficients implicites ; flag -2 ignore les quatre coefficients. Un flag non valide provoque une erreur.

ROTMG exige des entrées finies et protège ses produits/rapports avec des mantisses et exposants séparés. Le poids négatif d1 ou une forme indéfinie inadmissible produit la transformation zéro BLAS. Le dépassement de la plage d'exposants d'une sortie, y compris le sous-dépassement d'un coefficient non nul, provoque OverflowError avant modification de state. Les quatre coefficients explicités sont préservés pendant chaque redimensionnement.

DSDOT/SDSDOT réassocient la somme Float64 (sommes partielles SIMD, comme OpenBLAS), sans fast-math ; un résultat non fini est recalculé dans l'ordre. Les produits Float32 sont élargis avant multiplication ; leur précision étendue ne constitue pas une sommation exacte ou compensée. Les valeurs non finies suivent l'arithmétique IEEE ; les entrées ne sont jamais modifiées.

En v0.5, les opérations packed/banded exploitent les colonnes stockées, sans parcourir les zéros structurels. gbmv!, tpmv!, tpsv!, tbmv!, tbsv! et les mises à jour spr!/spr2!/hpr!/hpr2! acceptent kernel=:auto ou les demandes ISA déjà décrites pour GEMM ; :scalar choisit la boucle générique. Le SIMD explicite des mises à jour contiguës concerne les deux types réels. Les quatre types restent acceptés par les opérations compactes.

Les multiplications triangulaires se font en place dans l'ordre de dépendance, sans copie de x lorsqu'il ne recouvre pas les coefficients. Les résolutions vérifient tous les pivots non unité avant modification. Si les coefficients recouvrent la sortie, une copie du stockage utile protège les lectures. Les paddings et diagonales unité sont ignorés, y compris au packing.

Pour SYRK/HERK/SYR2K/HER2K/GEMMT, threaded=true peut maintenant répartir les tuiles indépendantes. GemmConfig.parallel_threshold contrôle le seuil ; workspace.buffers borne aussi le nombre de tâches. Chaque tâche possède un couple de panneaux et appelle GEMM en monothread ; le parent du workspace reste verrouillé pendant tout le plan. Les tampons diagonaux et contextes restent alloués par appel. threaded=false conserve l'exécution séquentielle ; un seul buffer peut aussi limiter le plan à une tâche. SYMM/HEMM conservent leur parallélisme GEMM, et les dépendances de TRMM/TRSM ne sont pas modifiées.
