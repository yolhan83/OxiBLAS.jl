Tensors

einsum and contractions

einsum(spec, A...) evaluates an Einstein notation on dense arrays, SparseTensors or sparse matrices. Pairwise contractions go through the native GEMM (TTGT).

using OxiBLAS
A = randn(16, 16, 16); B = randn(16, 16)
C = einsum("abc,cd->abd", A, B)            # allocating
P = plan_einsum("abc,cd->abd", A, B)       # reusable plan
D = similar(C); ws = EinsumWorkspace(Float64)
einsum!(D, P, A, B; workspace=ws)          # in place, reused workspace
D ≈ C
true
  • Plans. plan_einsum(spec, A...; optimize) chooses the contraction order: :greedy by default, :beam, :optimal, or :none for the direct contraction. A plan is immutable and thread-safe.
  • In-place evaluation. einsum!(C, plan, A...; α, β, workspace) writes into C. Temporaries come from the EinsumWorkspace.
  • Sliced plans. plan_einsum_sliced bounds the memory by slicing the computation; einsum_layout_report describes the chosen memory layouts.
  • Explicit contractions. contract(A, B, axesA, axesB) and contract! contract the given axes (explicit conjugations).
  • Specialized products. outer_product, mode_product(A, U, mode), batched_matmul and batched_matmul!.

Sparse tensors

SparseTensor(dims, coordinates, values) stores sorted linear indices (column-major order).

X = SparseTensor((30, 30, 30), [(rand(1:30), rand(1:30), rand(1:30)) for _ in 1:500], randn(500))
U = randn(30, 4)
Y = einsum("abc,cz->abz", X, U)            # sparse × dense
size(Y)
(30, 30, 4)
  • Sparse × sparse products use a column-wise SpGEMM on the unfoldings.
  • Matrix operands (CSR, CSC, SparseMatrixCSC, 2-D SparseTensor) stay in native CSC.
  • einsum! into a sparse destination receives the CSC result directly.
  • The result of a sparse computation is a SparseTensor.
