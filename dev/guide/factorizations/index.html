Dense factorizations and LAPACK

The dense engines are written in Julia and reuse the native GEMM for their blocked updates. Each one returns its own object (LUFactor, QRFactor…), usable with solve or through the high-level API, which wraps it in a LinearAlgebra.Factorization.

using OxiBLAS, LinearAlgebra
A = randn(80, 80) + 80I; b = randn(80)
F = lu_factor(A)                 # F.L*F.U ≈ A[F.p,:]
x = solve(F, b)
H = Hermitian(A * A')
C = cholesky_factor(Matrix(H))   # lower triangle, F.L*F.L' ≈ A
Q = qr_factor(randn(100, 40))    # least squares: least_squares(Q, y)
norm(A * x - b) / norm(b)
4.003131575510085e-16

SVD. The default Jacobi guarantees relative accuracy on small singular values, at several times the cost of gesdd. algorithm=:golub_kahan is the fast path (see the high-level suite in Performance).

Matrix functions

matrix_exp, matrix_log, matrix_sqrt, matrix_power, matrix_sign, matrix_sin, matrix_cos, the Fréchet derivatives (frechet_exp, frechet_log, frechet_sqrt, frechet_matrix), matrix_norm, kron_product, khatri_rao, kron_sum and kronecker_action. The high-level versions OxiBLAS.exp, log, sqrt, sin and cos keep the structure when it is guaranteed (see the high-level API).

Extended precision

The generic algorithms accept other floating-point types (BigFloat, Float16, extended-precision types provided by other packages), as do gemm_extended! and dot_extended.

Errors

SingularException and PosDefException are those of LinearAlgebra (re-exported under the same names). ConvergenceError reports that an iteration limit was reached.
