Factorisations denses et LAPACK

Les moteurs denses sont écrits en Julia et réutilisent le GEMM natif pour leurs mises à jour par blocs. Chacun renvoie un objet propre (LUFactor, QRFactor…), utilisable avec solve ou par l'API haut niveau, qui l'enveloppe dans une LinearAlgebra.Factorization.

using OxiBLAS, LinearAlgebra
A = randn(80, 80) + 80I; b = randn(80)
F = lu_factor(A)                 # F.L*F.U ≈ A[F.p,:]
x = solve(F, b)
H = Hermitian(A * A')
C = cholesky_factor(Matrix(H))   # triangle inférieur, F.L*F.L' ≈ A
Q = qr_factor(randn(100, 40))    # moindres carrés : least_squares(Q, y)
norm(A * x - b) / norm(b)
5.867188471036957e-16

SVD. Le Jacobi par défaut garantit une précision relative sur les petites valeurs singulières, au prix de plusieurs fois le coût de gesdd. algorithm=:golub_kahan est la voie rapide (voir le banc haut niveau, Performances).

Fonctions matricielles

matrix_exp, matrix_log, matrix_sqrt, matrix_power, matrix_sign, matrix_sin, matrix_cos, les dérivées de Fréchet (frechet_exp, frechet_log, frechet_sqrt, frechet_matrix), matrix_norm, kron_product, khatri_rao, kron_sum et kronecker_action. Les versions haut niveau OxiBLAS.exp, log, sqrt, sin et cos conservent la structure quand elle est garantie (voir API haut niveau).

Précision étendue

Les algorithmes génériques acceptent d'autres flottants (BigFloat, Float16, types de précision étendue fournis par d'autres paquets). Voir LOTPRECISIONETENDUE et gemm_extended!, dot_extended.

Erreurs

SingularException et PosDefException sont celles de LinearAlgebra (réexportées sous les mêmes noms). ConvergenceError signale une limite d'itérations atteinte.
