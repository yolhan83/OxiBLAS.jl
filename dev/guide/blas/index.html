BLAS 1, 2, 3 and matrix multiplication

Every function works on 1-based arrays. The optimized paths cover Float32, Float64, ComplexF32 and ComplexF64. Outputs must be mutable and free of repeated indices.

GEMM

using OxiBLAS
A = randn(Float32, 300, 200); B = randn(Float32, 200, 150); C = zeros(Float32, 300, 150)
gemm!(C, A, B)                           # C ← A·B
gemm!(C, A, B, 2f0, 1f0; transA=:N)      # C ← 2·A·B + C
G = zeros(Float32, 200, 200)
gemm!(G, A, A; transA=:C)                # G ← Aᴴ·A
kernel_info(Float32)
(architecture = :x86_64, cpu = "znver5", kind = :scalar, lanes = 1, mr = 4, nr = 4)
  • transA/transB are :N, :T or :C. Non-unit-stride views, transpose and adjoint are accepted.
  • An input that overlaps the output is copied before writing. β = 0 does not read the old output; α = 0 or k = 0 does not read the inputs.
  • algorithm selects a path: :auto, :reference, :blocked, :packed, :register, :simd. kernel is :auto, :scalar, :neon, :avx2 or :avx512; an unavailable ISA raises an error before anything is written.
  • Workspace. GemmWorkspace(T, m, n, k; config, workers) reserves reusable panels. Sharing it between calls is protected by a lock; for independent concurrent calls, use one workspace per task.
  • Parallelism. It is controlled by julia --threads=N, threaded=false and GemmConfig(parallel_threshold=...). The number of tasks follows the size of the product.
  • Variants: gemm_cache_oblivious!, gemm_strassen!, gemm_winograd! (explicitly chosen), gemm_batched!, gemm_strided_batched!, gemm_extended! (generic types).

OxiBLAS.mul! and OxiBLAS.mul

OxiBLAS.mul!(C, A, B, α, β) and OxiBLAS.mul(A, B) (not exported) dispatch to the right kernel from the types: dense GEMM, sparse × dense, sparse × sparse, structured matrices. A * B on the OxiBLAS sparse formats goes through the same layer.

The structured BLAS 3 routines reuse the GEMM engine and its options (algorithm, kernel, threaded, workspace, config). SYRK, HERK, SYR2K, HER2K and GEMMT can spread independent tiles across tasks.
