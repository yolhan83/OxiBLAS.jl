BLAS 1, 2, 3 et multiplication matricielle

Toutes les fonctions travaillent sur des tableaux indexés à partir de 1. Les chemins optimisés couvrent Float32, Float64, ComplexF32 et ComplexF64. Les sorties doivent être modifiables et sans indices répétés.

GEMM

using OxiBLAS
A = randn(Float32, 300, 200); B = randn(Float32, 200, 150); C = zeros(Float32, 300, 150)
gemm!(C, A, B)                           # C ← A·B
gemm!(C, A, B, 2f0, 1f0; transA=:N)      # C ← 2·A·B + C
G = zeros(Float32, 200, 200)
gemm!(G, A, A; transA=:C)                # G ← Aᴴ·A
kernel_info(Float32)
(architecture = :x86_64, cpu = "znver3", kind = :scalar, lanes = 1, mr = 4, nr = 4)
  • transA/transB valent :N, :T ou :C. Les vues à pas non unitaire, transpose et adjoint sont acceptés.
  • Une entrée qui recouvre la sortie est copiée avant l'écriture. β = 0 ne lit pas l'ancienne sortie ; α = 0 ou k = 0 ne lit pas les entrées.
  • algorithm choisit une voie : :auto, :reference, :blocked, :packed, :register, :simd. kernel vaut :auto, :scalar, :neon, :avx2 ou :avx512 ; une ISA indisponible provoque une erreur avant toute écriture.
  • Espace de travail. GemmWorkspace(T, m, n, k; config, workers) réserve des panneaux réutilisables. Son partage entre appels est protégé par un verrou ; pour des appels simultanés indépendants, il faut un espace par tâche.
  • Parallélisme. Il est contrôlé par julia --threads=N, threaded=false et GemmConfig(parallel_threshold=...). Le nombre de tâches suit la taille du produit.
  • Variantes : gemm_cache_oblivious!, gemm_strassen!, gemm_winograd! (choisies explicitement), gemm_batched!, gemm_strided_batched!, gemm_extended! (types génériques).

OxiBLAS.mul! et OxiBLAS.mul

OxiBLAS.mul!(C, A, B, α, β) et OxiBLAS.mul(A, B) (non exportés) dispatchent vers le bon noyau selon les types : GEMM dense, produit creux × dense, creux × creux, matrices structurées. A * B sur les formats creux OxiBLAS passe par la même couche.

Les BLAS 3 structurés réutilisent le moteur GEMM et ses options (algorithm, kernel, threaded, workspace, config). SYRK, HERK, SYR2K, HER2K et GEMMT peuvent répartir des tuiles indépendantes entre tâches.
