API haut niveau

L'API haut niveau reprend les noms et les conventions de LinearAlgebra, au-dessus des moteurs natifs.

  • Des fonctions propres à OxiBLAS. OxiBLAS.lu !== LinearAlgebra.lu. Elles ne sont pas exportées : on écrit OxiBLAS.lu(A), OxiBLAS.ldiv(F, b).
  • Les types LinearAlgebra. Les factorisations (OxiBLAS.LU, OxiBLAS.Cholesky, OxiBLAS.QR…) sont des sous-types de LinearAlgebra.Factorization : F \ b, ldiv!(Y, F, b), F', inv(F), det(F) fonctionnent comme pour les factorisations de LinearAlgebra.
  • Pas de repli caché. Sur une matrice qu'aucun moteur OxiBLAS ne prend en charge, l'appel renvoie une MethodError, jamais un calcul BLAS/LAPACK silencieux.
using OxiBLAS, LinearAlgebra
A = randn(60, 60) + 60I; B = randn(60, 3)
F = OxiBLAS.lu(A)
X = F \ B                       # générique LinearAlgebra, primitives OxiBLAS
F2 = OxiBLAS.factorize(Hermitian(A * A' + I))   # Cholesky choisi par la structure
S = OxiBLAS.svd(randn(40, 20))
(typeof(F2), size(S.U), norm(A * X - B) < 1e-10)
(OxiBLAS.Cholesky{Float64, CholeskyFactor{Float64, Matrix{Float64}}}, (40, 20), true)

using SparseArrays
S = sprand(300, 300, 0.01) + 10I; A = CSRMatrix(S); b = randn(300)
F = OxiBLAS.factorize(A)
x1 = A \ b; x2 = OxiBLAS.ldiv(F, b); y = similar(b); OxiBLAS.ldiv!(y, A, b)
x1 ≈ x2 ≈ y
true
  • Dimensions. B a size(F, 1) lignes et Y en a size(F, 2).
  • Systèmes rectangulaires. Un système haut donne la solution des moindres carrés.
  • Résolution en place. Y === B est autorisé pour un système carré. Un chevauchement partiel entre Y et B est refusé.
  • Second membre et destination. Un B creux est lu via une copie dense. Une destination creuse est refusée : la solution est dense.
  • Précision. Le calcul se fait dans le type de la factorisation. Un facteur réel et un B complexe de même précision sont résolus comme deux systèmes réels.

Limitations

  • Systèmes creux.
    • Un système creux large (sous-déterminé) n'est pas résolu : la QR creuse exige m ≥ n.
    • La QR creuse n'est pas révélatrice du rang : F \ b lève SingularException si R est numériquement déficient.
  • Absence d'état d'échec. Les moteurs creux (LU, Cholesky) et le LDLᵀ dense lèvent l'exception standard même avec check=false.
  • Options refusées.
    • bunchkaufman(A, true) (pivot rook) n'est pas disponible.
    • Un PackedMatrix indéfini n'a pas de factorisation indéfinie.
  • Pas de solve. Eigen, Schur et Hessenberg n'ont pas de primitive de résolution, comme dans LinearAlgebra.
